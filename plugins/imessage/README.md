# @chronicle.app/imessage

Read `chat.db` with `ImessageExtractor`, then emit MessageAction/Message records with `ImessageTransformer`. Sending a message brings it into being, so the `Message` is the action's `result`. `input` defaults to the macOS Messages database; use a consistent backup for exported data. Reading it needs Full Disk Access for the app that runs Chronicle (Terminal, iTerm, your editor): System Settings → Privacy & Security → Full Disk Access. Without it the run stops with that hint, not SQLite's `unable to open database file`. The connection is read-only via built-in `node:sqlite`. Date windows are exclusive, records newest-first, and `limit: 0` means unlimited.

A message in a group chat is part of the group's `Channel` (`isPartOf`), keyed in the `imessage` namespace by Apple's ID for the group: `original_group_id`, the ID it started with, `sameAs` `group_id` when Messages replaced it. `groupChatChannel` in `@chronicle.app/apple` builds it, and the Apple Photos plugin's Shared with You keys the same group with it. Each device keeps its own `chat_identifier` for a chat, so that isn't the key. The Channel's `name` is the group's name when it has one, and its `member` edges are the chat's participants other than you, from the first message a run reads in the chat. A group message's recipients are still each other participant and you. A one-to-one chat has no `Channel`.

Automatic iCloud account and AddressBook enrichment comes from `@chronicle.app/apple`. `includeContactNames: false` skips contacts. An explicit `account` object (or null) lets callers describe exported data without host account lookup. Transformer config can inject `lookupContact` for exported contacts. Missing permissions/account/contact data fall back to source-local identity and unlabelled participants. When no identifier for the account owner is available, the owner is left out of the agent and recipients.

Attachments are local file references with MIME metadata, not copied bytes. Missing files are skipped. Attributed-body decoding retains the existing heuristic; it is not a complete typedstream decoder. Raw records preserve the source blob, and large integer timestamps are decimal strings so serialization is safe.

The plugin declares a `deepLinks` template for `Message` (`messages://open?message-guid=<GUID>`), so a host can open the message in Messages. SMS messages are linked the same way, since they are in `chat.db` too. Attachments are not linked, because an attachment's GUID is not a message GUID.

Tests use synthetic Messages and AddressBook databases, account command fixtures, and temporary attachment files. They do not read personal messages or contacts.
