# @chronicle.app/apple-notes

Notes from Apple Notes on a Mac, who made each one, and who wrote what in them, when.

## Usage

```sh
chronicle extract apple-notes
chronicle extract apple-notes --since 2026-10-01
chronicle extract apple-notes -t edits --since 2026-10-01
chronicle extract apple-notes -t notes,edits --session-gap 5
chronicle extract apple-notes --input "/path/to/NoteStore.sqlite"
```

The store is `~/Library/Group Containers/group.com.apple.notes/NoteStore.sqlite`, opened read-only with built-in `node:sqlite`. Reading it needs Full Disk Access. Attachments are found in the `Accounts` folder beside it.

There are two record types. A bare run extracts `notes`; `-t edits` extracts edits, and `-t notes,edits` both:

- `notes`: each note as it is now, last edited first. `--since` and `--until` bound when each was last edited, so a run since the last one picks up every note changed since.
- `edits`: bursts of one person's writing in one note, newest first. `--since` and `--until` bound when each ended. `--session-gap` sets how many minutes without writing end a burst, 20 by default, and a run that gives it and names no types reads edits.

### Decisions

**A note is a `Note`, not a file.** A `MediaObject` such as a `DocumentObject` is a file, with a path and a media type. A note has neither: Notes keeps its text as a CRDT inside the database, and the Markdown in `body` is a rendering of it. The note keeps its ID however often it's edited; `notes` is a snapshot of each note as it is now, and `edits` is how it got there. As a snapshot, a note states all its text, hashtags, and attachments, even when it has none, so deleting the last of them closes the old ones. A note whose text can't be read says nothing about its text or hashtags.

**A note is its last edit, and when it was made.** Most people want their notes with a time or two, not how they were written, so `notes` gives each note as an `UpdateAction` at its last edit, whose `object` is the note as it has been since, and a `CreateAction` for when it was made and by whom. Nothing in the vocabulary lets a note name the action that made it, so the two are separate actions that share the note by its key. The last edit is when Notes last saved the note, or when its newest text was written, if later: text that syncs in from someone else can leave the save time behind. It's by whoever wrote the newest text, so an edit that left no text, such as a deletion, is credited to whoever typed last; a note with no write times is by the one person it maps any replica to, or no one. A run that finds a later edit adds an action, and earlier ones stay. `edits` runs only when asked for, and its bursts are separate actions: one says when the note was last changed and what it holds, the other who wrote what.

**Notes records when text was written, not each edit.** Since 2021 (iOS 15), Notes stamps each stretch of text with the second it was written. Text from before then has no time, and deleted text is kept only as a tombstone with a length and no characters, so neither what was deleted nor when can be recovered. An edit is a burst of writing whose text is still in the note: the stretches one person wrote with no gap longer than `--session-gap` between them. A burst whose text was all deleted later doesn't appear, and one whose earliest text was deleted starts later, which changes its key. Two people who start writing in a note in the same second are two edits, so the key names who wrote it.

**Who wrote it comes from the note.** Notes records each character's replica, one Notes install on one device, and each note maps every replica that edited it to a CloudKit user ID. The account's own ID is you. So a shared note's text is credited to whoever typed it, and a burst that two people wrote at the same time is two edits. A replica the note doesn't map has no `agent`. The replica itself isn't kept: Notes doesn't record which device or app it is, so it would be a node with nothing but an ID. A note's maker is the creator its CloudKit record names; a note never synced to iCloud was made on this Mac.

**You are your Apple Account.** The iCloud account in Notes is the Mac's Apple Account, so you're the same `Person` the other Apple plugins make, keyed by its DSID and tagged `@me`. With no Apple Account signed in, you're keyed by your CloudKit user ID in Notes instead, still tagged `@me`.

**Anyone else is keyed by their CloudKit user ID in Notes.** CloudKit, the service Notes syncs through, gives each Apple Account a different ID in each app and never shows anyone else's Apple Account. So the ID is the same in every note but matches nothing outside Notes, and a person's emails and phone numbers link them to the same person in other sources: email by address, and messages and calls by number. They come from the shares in the database, which list each person by the address they were invited at, with the name iCloud has for them. A person invited at different addresses in different shares keeps them all, and someone named in any share is named in every note. Each address is looked up in Contacts, as Call History does, and a card it finds adds its other emails and numbers and is linked itself. iCloud writes a phone number with its country code and no plus; numbers are normalized to E.164.

**A folder is keyed within its owner's account.** Notes names its own folders the same in every account, such as `DefaultFolder-CloudKit` for Notes and `TrashFolder-CloudKit` for Recently Deleted, so a folder's ID is unique only within the account it's in. A folder is `inAccount` whoever owns it, by their CloudKit user ID, which is theirs on every device: you for your own folders, tagged `@me`, and whoever shared a folder with you for theirs. So two accounts' Notes folders are two folders, and a folder synced to two Macs is one.

**What a burst added is a `Changeset` of the note.** The burst updated the note, and the changeset is the change it made. It isn't a `Revision`, a version of the whole note, because Notes can't rebuild the note as it was. Its `body` is the text from the burst that's still in the note, in order, with an ellipsis line between pieces that aren't next to each other. It's Markdown, as the note's `body` is: a line keeps its heading, list, or checklist marker when the burst started it, and text added to the end of an earlier line has none. The edit is dated by its burst, but what it says about the note, its title and the text still in it, is as of the extraction, so it doesn't backdate a later title or deletion.

**Files and drawings are attachments; tables and link previews aren't.** Images, drawings, PDFs, scans, audio, and video are the note's `contains`, with the file's path when it's downloaded to this Mac. Editing a photo can leave its earlier versions beside it, so the path is the current one, in the folder the attachment's media names. A drawing has no file of its own, in Notes' current format or the one before it, but Notes keeps an image of it for wherever it can't draw it, so a drawing is an `ImageObject` with that image's path, as a photo is. Nor does a document you can mark up, such as a PDF added to a note: Notes keeps the PDF inside a format of its own, so the document's path is the PDF Notes renders of it, with any markup. Tables and link previews have no file, so they're left out, and the body names them in brackets, such as `[table]`. In the body, a file is a Markdown image or link to `cid:` and the identity of its node in `contains`, the hash of its key that `nodeKey` in `@chronicle.app/schema` gives, as an email's inline image names its part, such as `![photo.jpeg](cid:…)`, downloaded or not. Not its path, which is only on this Mac, or its name, which several photos in one note can share.

**Some notes have less.** A locked note's text is encrypted, so it has no body and no edits. A note marked for deletion is left out; one in Recently Deleted is in that folder. Text Notes stored in a form this plugin can't read is left out with a warning, as is who edited a note when its map of them can't be read, and the run goes on.

**The columns are current macOS's.** Core Data numbers column names such as `ZTITLE1`, and an older or newer macOS can number them differently.

## Tests

The tests build a synthetic `NoteStore.sqlite` with `node:sqlite`, with note bodies, replica maps, and CloudKit records and shares encoded by the test helper, an image beside it, edited once, so its earlier version is there too, and what Notes keeps of a drawing and a PDF. They never read the host's Notes.
