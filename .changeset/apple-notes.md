Add the Apple Notes plugin, run as `chronicle extract apple-notes`. It extracts each note in Notes on a Mac, as its last edit and when it was made, and, when asked for with `-t edits`, the bursts of writing still in each one, credited to whoever typed them. A note is an `UpdateAction` at its last edit, whose `object` is the `Note`, keyed by its ID, with its text as Markdown, its hashtags as `tags`, its folder as a `Collection` in the account of whoever owns it, and its image, drawing, PDF, scan, audio, and video attachments under `contains`, and a `CreateAction` by whoever made it. `--since` bounds when each note was last edited, so an incremental run picks up every note changed since. Notes stamps each stretch of text with when it was written and each character with the Notes install that typed it, which each note maps to a person's CloudKit user ID. So `edits` gives each burst of one person's writing as an `UpdateAction` of the note, with its start and end, and the text from it that's still in the note as a `Changeset`, the change it made. You are your Apple Account, as in the other Apple plugins. Anyone else is keyed by their CloudKit user ID in Notes, named from the note's shares, and linked to the same person in other sources by every email and number the shares list, and by the Contacts card each one finds, with its other emails and numbers.

The vocabulary adds `Note`: a text that its author keeps and edits, such as a note in a notes app or a page in a personal wiki, as against a `DocumentObject`, which is a file. A `Changeset` can be a change applied directly, as the `result` of the `UpdateAction` that made it, as well as a proposal such as a pull request. Its `body` is the text it adds. `nodeKey` gives a node's identity, the hash of the keyset its `@key` names, as a store derives it, so one node can name another, as a note's text names a photo in it as `cid:` and that identity.
